### 已實作的設定方式

沿用「站台選項」頁，改為「連線保持（防閒置）」，保留啟用開關與自訂字串。

方式分為三種：

- 自動：`ptt.cc`／`ptt2.cc` 及其子網域使用 TIMING-MARK；其他主機沿用自訂字串。
- TIMING-MARK：固定使用協定指令，適合以 IP／其他別名連接 PTT 時明確指定；字串欄停用。
- 自訂字串：保留舊行為，即使連到 PTT 也尊重明確選擇，但提示可能干擾操作。留空不傳送資料，不是 NUL。

預設仍啟用、180 秒；有效範圍 30～86400 秒，建議 180～300 秒。
INI 中非法值回復 180 秒；UI 啟用且可編輯時拒絕非法秒數。
舊全域／自訂站台設定沒有 `idle_mode` 時採自動；使用全域設定的站台繼承全域模式。
自動模式的字串欄仍可編輯，因為其他主機會用到；關閉功能或使用全域設定時停用相應欄位。
連線保持不等於自動重連，也不保證站台不會中斷連線。

人工驗收交由使用者操作，步驟見 [Keep-Alive 測試說明](../Tests/README.md#keep-alive-人工驗收)。
先前獨立 UI 測試副本曾出現 Runtime Library 提示，原因未確認；其結果不作為 UI 通過的依據。
請使用原建置輸出目錄內的程式測試，不使用 `Tests/bin/UiSmoke` 副本。

主要涉及：`Resource/Common.rc`、`Resource/resource.h`、`Lite/SitePage.cpp/.h`、
`Lite/SiteSettings.cpp/.h`、`Lite/AppConfig.cpp`、`Lite/TermView.cpp`、`Lite/TelnetConn.cpp`、`Lite/RFC854.h`。

## 後續驗證重點

### DEC2026 同步更新

詳見 [實作範圍與驗收方式](DEC2026-Validation.md)。本機慢速輸出腳本只監聽 127.0.0.1，
讓使用者比較逐行刷新與同步呈現；代理未自動操作 GUI 或登入站台。
逾時門檻 2 秒（計時器檢查通常 2～3 秒解除），逾時／斷線／尺寸變更不等於文章完成。
原始資料觸發器不變；合併多模式私有指令與模式查詢仍安全忽略，未宣稱完整 ECMA-48。

### 新介面回歸測試

檢查結果、驗證範圍與 R1～R10 人工步驟見 [新介面回歸驗證](PTT-Interface-Regression.md)。
本輪未修改正式程式或個人設定，只增加測試與文件；未自動操作 UI。
未發現內建列表辨識依賴舊標籤；自訂觸發器／巨集仍可能受文字、色碼及按鍵流程變更影響。
觸發器原始區塊比對的長度／分段／重複觸發風險另記於文件，尚未修正，不視為已驗收。
公告的 PTT1 標題／底列與動態指令列更新分別為 10/04、預定 10/18；目前 PTT1 正常不等於所有新版驗證通過。

### 整篇文章複製安全修正

- 新增 `Lite/ArticleProgress.h`：僅讀底列可見文字寬度，明確區分未完成／100% 完成／無有效資料。
- 百分比限 0～100，行號須為正整數且遞增範圍合理，防止整數溢位；要求完整的「行」單位（Big5／UTF-8）。
- 不依賴右側按鍵提示。橫向捲動的欄位範圍、非相容格式保守拒絕，不猜測行號。
- 開始時無法辨識進度會提示，不送出方向鍵、不覆寫剪貼簿。
- 接收過程底列不完整／重複／倒退／跳行過大時等待；只接受新增 1～2 行，避免重複收錄與盲目送鍵，等待時可取消。
- 「播放動畫」共用進度檢查亦明確判斷狀態；無效資料停止送空白鍵，而非視為尚未完成繼續操作。
- 自動測試擷取正式進度讀取／開始複製／續傳方法，UI、按鍵傳送、ANSI 文字產生與剪貼簿完成端使用替身；不宣稱驗證實際繪圖／剪貼簿。
- 限制：仍依賴螢幕內容；後續 DEC2026 實作會在同步期間阻止擷取，但未包在同步指令內的資料仍不能完全辨別新舊畫面混合。本次不重寫整套下載器或增加自動重試。
- 人工驗收步驟見 [文章複製測試](../Tests/README.md#文章複製人工驗收)，由使用者執行。

- 整篇文章複製：正常／空白／缺少 `~`／非法行號／缺少百分比／分段更新；無有效資料時不得越界、誤判完成或盲目翻頁。
- 新介面：文章底列左側進度格式依公告不變，不依賴右側提示文字；看板資訊使用 `q`／左方向鍵離開。
- PTT2 與 PTT1 新舊畫面都需確認；站台公告日期不等於已完成實際部署驗證。
